Pernyataan Aksesibilitas

♿ Komitmen Kami

GasLamar berkomitmen untuk memastikan aksesibilitas digital bagi semua orang, termasuk penyandang disabilitas. Kami terus berupaya meningkatkan pengalaman pengguna dan menerapkan standar aksesibilitas yang relevan.

Target kami adalah memenuhi WCAG 2.1 Level AA (Web Content Accessibility Guidelines versi 2.1, tingkat kepatuhan AA) di seluruh antarmuka GasLamar.

📊 Status Kepatuhan

GasLamar sebagian memenuhi WCAG 2.1 Level AA. Kami secara aktif mengidentifikasi dan memperbaiki area yang belum sepenuhnya memenuhi standar ini.

Langkah-langkah yang telah diterapkan antara lain:

  • Skip-to-content link di setiap halaman utama untuk pengguna keyboard
  • Ukuran touch target minimal 44×44 px untuk semua elemen interaktif
  • Label aria-label dan aria-describedby pada form dan elemen dinamis
  • Rasio kontras warna yang memenuhi WCAG AA (minimal 4.5:1 untuk teks normal)
  • Struktur heading yang hierarkis dan semantik HTML yang benar
  • Atribut alt pada semua gambar bermakna
  • Navigasi keyboard penuh tanpa memerlukan mouse

⚠️ Keterbatasan yang Diketahui

Area berikut masih dalam proses perbaikan:

  • Beberapa komponen animasi mungkin belum sepenuhnya mengikuti preferensi prefers-reduced-motion
  • Dokumen CV yang dihasilkan (PDF/DOCX) belum dioptimalkan untuk screen reader — ini merupakan keterbatasan format file, bukan antarmuka web

Jika kamu menemukan hambatan aksesibilitas lain, harap beritahu kami melalui kontak di bawah.

🔍 Panduan QA Aksesibilitas — Tombol Submit

Tombol submit pada halaman upload menggunakan properti disabled HTML native — bukan aria-disabled. Ini adalah pola yang benar dan direkomendasikan.

Mengapa hanya disabled native?

  • Browser secara otomatis mengumumkan tombol disabled sebagai "tidak tersedia" (dimmed/unavailable/grayed out) kepada screen reader — tanpa perlu aria-disabled.
  • Menggunakan aria-disabled="true" sekaligus dengan disabled menyebabkan screen reader mengumumkan status dua kali (double-announcement) pada beberapa AT.
  • aria-disabled hanya diperlukan bila kamu ingin elemen tetap focusable meski dinonaktifkan — skenario yang tidak berlaku untuk tombol submit ini.

Perhatian saat inspeksi DOM

Panel Accessibility di DevTools (Chrome/Firefox) menampilkan properti aksesibilitas yang dikalkulasi — termasuk entri aria-disabled: true yang berasal dari atribut disabled native. Ini bukan atribut DOM yang sesungguhnya. Untuk memverifikasi apakah aria-disabled benar-benar ada di HTML, gunakan panel Elements atau jalankan:

document.getElementById('submit-btn').hasAttribute('aria-disabled')
// harus mengembalikan: false

Skenario yang diharapkan

  • Form tidak lengkap: tombol disabled (native), tidak ada aria-disabled, screen reader mengumumkan "tidak tersedia".
  • Form lengkap: tombol enabled, tidak ada aria-disabled, screen reader mengumumkan label tombol normal.
  • Sedang menganalisis: tombol disabled (native), tidak ada aria-disabled, label berubah menjadi "Sedang menganalisis CV kamu".

Perilaku ini diverifikasi secara otomatis oleh Playwright e2e test (tests/e2e/upload-button-a11y.spec.ts) pada setiap CI run.

♿ Our Commitment

GasLamar is committed to ensuring digital accessibility for people with disabilities. We continually improve the user experience and apply relevant accessibility standards.

Our target is conformance with WCAG 2.1 Level AA (Web Content Accessibility Guidelines version 2.1, conformance level AA) across all GasLamar interfaces.

Measures already in place include:

  • Skip-to-content link on every main page for keyboard users
  • Minimum 44×44 px touch targets for all interactive elements
  • Appropriate aria-label and aria-describedby attributes on forms and dynamic elements

  • alt attributes on all meaningful images
  • Full keyboard navigation without requiring a mouse

The following areas are still being improved:

  • Some animated components may not yet fully respect the prefers-reduced-motion media query
  • Generated CV documents (PDF/DOCX) are not screen-reader optimised — this is a limitation of the file format, not the web interface

If you encounter any other accessibility barriers, please let us know using the contact below.

🔍 QA Accessibility Guidance — Submit Button

The upload page submit button uses the native HTML disabled property — not aria-disabled. This is the correct and recommended pattern.

Why only native disabled?

  • Browsers automatically announce a disabled button as "unavailable" / "dimmed" / "grayed out" to screen readers — no aria-disabled is required.
  • Combining aria-disabled="true" with the native disabled attribute causes some assistive technologies to announce the state twice (double-announcement).
  • aria-disabled is only necessary when an element must remain focusable despite being inactive — that is not the case here.

Inspecting the DOM correctly

The browser's Accessibility panel (Chrome DevTools / Firefox) displays computed accessibility properties. It will show aria-disabled: true derived from the native disabled attribute — this is not an actual DOM attribute. To verify whether aria-disabled is truly present in the HTML, use the Elements panel or run:

document.getElementById('submit-btn').hasAttribute('aria-disabled')
// must return: false

Expected states

  • Form incomplete: button is disabled (native), no aria-disabled, screen reader announces "unavailable".
  • Form complete: button is enabled, no aria-disabled, screen reader announces the button label normally.
  • Analysing in progress: button is disabled (native), no aria-disabled, label changes to "Menganalisis CV kamu…".

These states are verified automatically by the Playwright e2e test (tests/e2e/upload-button-a11y.spec.ts) on every CI run.
